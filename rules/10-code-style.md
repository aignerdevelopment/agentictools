# Code style

- Match the surrounding code's style, naming and idioms before introducing new
  patterns.
- Read the file (and its imports) before editing it.
- Make the smallest change that solves the problem. Do not refactor unrelated
  code in the same change.
- Do not add comments unless they explain *why*, not *what*.
- Remove dead code you introduce; leave pre-existing dead code alone.
- Prefer existing libraries and utilities in the project over new dependencies.
